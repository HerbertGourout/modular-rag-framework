# Global Instructions — Modular RAG Framework

This file provides **mandatory architecture rules** that apply to all code you generate for this project. Violating these rules will break tests and architecture conformance. Read carefully.

---

## 1. Hexagonal Layering Rules (ref. ADR-0001)

### Dependency Flow (One Direction Only)
```
cli/ + api/  →  app/  →  orchestration/  →  contracts/ + core/
                                               ↑
                        domain modules  ─────┘
                        (ingestion, retrieval, generation,
                         security, agents, memory, eval)
                                               ↑
                        adapters/  ────────────┘
```

### Absolute Rules
1. **`core/`** imports NOTHING from this project. It is the foundation.
2. **`contracts/`** imports ONLY `core/`. It defines all Protocols (interfaces).
3. **Domain modules** (`ingestion/`, `retrieval/`, `generation/`, `security/`, `agents/`, `memory/`, `eval/`) import ONLY:
   - `contracts/` (Protocol interfaces)
   - `core/models/` (Pydantic models, enums, errors)
   - **NEVER from each other** (e.g., `retrieval/` cannot import from `generation/`)
4. **`adapters/`** imports:
   - `contracts/` + `core/` + external libraries (qdrant-client, rank-bm25, sentence-transformers, openai, anthropic, fitz)
   - **NEVER from domain modules**
5. **`app/`, `orchestration/`, `cli/`, `api/`** may import from all below them. They are top-level.

### Common Violations to Avoid
- ❌ `retrieval/bm25_retriever.py` imports from `generation/openai_generator.py` → **FORBIDDEN**
- ❌ `security/guard.py` imports from `ingestion/chunker.py` → **FORBIDDEN**
- ❌ `adapters/embeddings/hf_embedder.py` imports from `retrieval/` → **FORBIDDEN**
- ✅ `retrieval/bm25_retriever.py` imports from `contracts/retrieval.py` + `core/models/document.py` → **CORRECT**

## 2. Component Wiring Pattern (ref. ADR-0002)

### Rule: Wire Only via Registry + YAML Manifests
**NEVER** wire a component directly in Python code. Always use the manifest YAML pattern.

### Correct Flow
1. Implement a Protocol in `contracts/` (e.g., `Chunker`)
2. Create concrete implementation in domain module (e.g., `ingestion/chunkers/fixed.py`)
3. Register in `app/default_factories.py`; `orchestration/` may only import
   core/contracts/orchestration, not concrete adapter implementations
4. **Select by name in manifest YAML** (e.g., `manifests/presets/local-hybrid-rag.yaml`)

### Examples
```python
# ❌ WRONG — do not wire in Python
from modular_rag.ingestion.chunkers.fixed import FixedSizeChunker
chunker = FixedSizeChunker(chunk_size=512)  # Don't do this

# ✅ CORRECT — register in app/default_factories.py, select in manifest
# In app/default_factories.py, inside register_defaults():
reg.register("chunker", "fixed", lambda cfg: FixedSizeChunker(**cfg.config))

# In manifests/my_pipeline.yaml — top-level field, no `components:` wrapper:
chunker:
  type: "fixed"
  config:
    chunk_size: 512
```

## 3. Observability: Three Separate Signals

- `TraceStep`/`Trace` is framework evidence recorded after a request through optional `Telemetry`.
  `RAGEngine` currently emits query-guard, retrieval, reranking and generation steps; generators
  provide token/model metadata. Do not add a `Trace` parameter to domain Protocols just to emit it.
- `Tracer` creates live distributed spans. Instrument orchestration, application and API
  boundaries; the OTel adapter lives in `adapters/observability/otel_tracing.py`.
- `Meter` emits operational counters, histograms and gauges. Instrument the same boundary layers,
  keep labels bounded, and never add request/document/tenant identifiers as metric attributes.

New execution stages need an explicit observability decision and tests, but must preserve contract
signatures and layer boundaries. See `docs/guides/observability.md`, ADR-0012 and ADR-0013.

## 4. Lazy Imports for Heavy Dependencies

Heavy external libraries **MUST** be imported inside the function that uses them, **NOT at module level**. This keeps domain modules lightweight and testable.

### Heavy Libraries (Lazy Import Required)
- `qdrant_client` (Qdrant vectorstore)
- `rank_bm25` (BM25 retriever)
- `sentence_transformers` (Hugging Face embeddings)
- `openai` (OpenAI LLM)
- `anthropic` (Anthropic LLM)
- `fitz` (PDF parsing)

### Correct Pattern
```python
# ❌ WRONG — imports at module level
from sentence_transformers import SentenceTransformer

class HFEmbedder:
    def __init__(self):
        self.model = SentenceTransformer("all-MiniLM-L6-v2")

# ✅ CORRECT — lazy import inside method
class HFEmbedder:
    def __init__(self, model_name: str = "all-MiniLM-L6-v2"):
        self.model_name = model_name
        self._model = None  # Lazy-loaded
    
    def _get_model(self):
        if self._model is None:
            from sentence_transformers import SentenceTransformer
            self._model = SentenceTransformer(self.model_name)
        return self._model
    
    def embed(self, texts: list[str]) -> list[list[float]]:
        model = self._get_model()
        return model.encode(texts).tolist()
```

## 5. Module Responsibilities (Quick Reference)

| Module | Responsibility | Examples |
|--------|---|---|
| **core/** | Enums, IDs, errors, Pydantic models | `Document`, `Chunk`, `Query`, `TraceStep` |
| **contracts/** | Protocol interfaces (typing.Protocol) | `Chunker`, `Retriever`, `Generator`, `SecurityGuard` |
| **ingestion/** | Parsers, normalizers, enrichers, chunkers | `FixedSizeChunker`, `RecursiveChunker`, `PDFParser` |
| **retrieval/** | Retrieval engines (BM25, vector, hybrid, rerankers) | `BM25Retriever`, `VectorRetriever`, `HybridRetriever` |
| **generation/** | LLM generators, citation builders | `OpenAIGenerator`, `AnthropicGenerator` |
| **security/** | Guards, redaction, inline policies, tenant isolation, audit/review | `BasicSecurityGuard`, `PatternRedactor`, `PolicyEngine` |
| **agents/** | Agent orchestration — generic multi-agent coordination is delegated to the external engine (ADR-0005); this module hosts the adapter integration, not a native `Coordinator`/`Planner` runtime | Engine-adapter glue code |
| **memory/** | Key/value storage only | `InMemoryStorage` |
| **eval/** | Exact match, retrieval metrics, benchmarks and gates | `ExactMatchEvaluator`, `BenchmarkRunner`, `QualityGate` |
| **adapters/** | External bindings (not domain logic) | `QdrantStore`, `HuggingFaceEmbedder`, `LangGraphEngineAdapter`, `OtelTracer` |
| **orchestration/** | RAGEngine, registry/container, engine adapters, state machine, reconciliation | Component wiring and execution flow |

## 6. Testing Structure (Quick Reference)

| Scope | Marker | Requires | Purpose |
|---|---|---|---|
| **Unit** | `tests/unit/` | Nothing | Fast, no external services |
| **Contract** | `tests/contract/` | Nothing | Protocol conformance (isinstance checks) |
| **Integration** | `tests/integration/` + `@pytest.mark.integration` | Qdrant on localhost:6333 | Real vector store |
| **E2E** | `tests/e2e/` + `@pytest.mark.e2e` | Qdrant + LLM API key | Full pipeline |

### Running Tests
```bash
pytest tests/unit                           # Fast baseline
pytest tests/contract                       # Protocol conformance
pytest tests/integration -m integration     # With Qdrant
pytest tests/e2e -m e2e                     # Full pipeline (requires LLM)
```

## 7. Version Scope (V1 vs V2+)

### V1 (Current Sprint) — Core RAG Only
- ✅ Ingestion (chunking, normalization)
- ✅ Retrieval (BM25, vector, hybrid, reranking)
- ✅ Generation (citation, groundedness)
- ✅ Security (guards, redaction, basic policies)
- ✅ Orchestration (RAGEngine, basic routing)
- ✅ Observability (`TraceStep`/`Telemetry`, OTel `Tracer`, OTel `Meter`)

### V2+ — Delegated, not merely deferred (per [ADR-0005](../docs/adr/0005-document-ai-control-plane-boundary.md), accepted 2026-08-04)
- ⚙️ Agent coordination (Coordinator, Planner, Retriever agents) — delegated to the selected external engine, not built natively
- ⚙️ Tool use / multi-turn patterns — same, engine-owned
- ⚙️ Graph-based memory traversal — delegated; the unused native graph data model was removed
- ✅ Policy Engine — **not** deferred; owned and current per ADR-0005 §5.1 (see `.claude/agents/security-specialist.md`)

### Rule
**DO NOT reimplement delegated capabilities natively.**

`adapters/llms/` contains the current
LangGraph adapter; `adapters/graphstores/` and `adapters/search/` remain empty extension targets.
`adapters/auth/` contains the real Keycloak verifier. `examples/simple_qa/` is complete; consult the
capability matrix for the next unimplemented capability instead of assuming version status.

## 9. Code Style & Conventions

- **Type hints**: Always. Use `Pydantic` models for data, `typing.Protocol` for interfaces.
- **Docstrings**: Google style, mandatory for public methods.
- **Error handling**: Raise custom errors from `core/errors.py` (e.g., `IngestError`, `RetrievalError`).
- **Imports**: Group by standard lib, third-party, then local. Use absolute imports (`from modular_rag...`).
- **File naming**: Snake case (`my_module.py`), test files mirror source structure.

---

## Summary: Do This, Never Do That

### ✅ DO
- Import from `contracts/` and `core/models/` in domain modules
- Wire components via manifest YAML + `orchestration/registry.py`
- Make an explicit Trace/Tracer/Meter decision for new execution stages
- Use lazy imports for heavy dependencies
- Write tests in the correct scope (unit/contract/integration/e2e)
- Reference ADR-0001, ADR-0002, ADR-0003 for structural questions

### ❌ NEVER
- Import from domain module to another domain module
- Wire components directly in Python code
- Add observability by changing a domain Protocol signature or introducing unbounded metric labels
- Import heavy libraries at module level
- Implement V2+ features without explicit request
- Modify contract Protocols without updating conformance tests
- Create new top-level modules without an ADR
