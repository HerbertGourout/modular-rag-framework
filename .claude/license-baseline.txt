# Dependency licence-gate baseline (Lot 16b, docs/refactoring-plan.md).
# Format: <package name, case-insensitive>=<reason accepted>
# scripts/check_licenses.py fails on any non-permissive-licence dependency
# NOT listed here. Adding an entry is a deliberate accept, not a default --
# see docs/refactoring/lot-16b-supply-chain.md for how each one was reviewed.

# AGPL-3.0 / Artifex Commercial dual license. Used for PDF parsing (`fitz`,
# lazy-imported per .claude/.instructions.md section 4) in the v1 and v5
# optional-dependency extras. AGPL's network-copyleft clause is a real
# constraint for any commercial/enterprise deployment that distributes this
# framework as a service -- flagged to Herbert Gourout in Lot 16b as a
# decision requiring explicit sign-off (keep and accept the AGPL obligation,
# obtain an Artifex commercial licence, or replace with a permissively
# licensed PDF library such as pypdf/pdfplumber). Recorded here as a
# currently-accepted risk, not a resolved one -- see the decision record for
# the actual outcome once decided.
pymupdf=AGPL-3.0/Artifex dual license; PDF parsing dependency; pending explicit accept/replace decision (Lot 16b)

# LGPLv2+. Low risk: an indirect/transitive dependency (charset detection,
# not linked/modified by this project's own code), and LGPL explicitly
# permits normal dependency use without imposing LGPL terms on the
# depending project, unlike GPL/AGPL's stronger copyleft.
chardet=LGPLv2+; transitive dependency, standard dynamic-dependency use permitted under LGPL terms

# LGPL-3.0-only. The PostgreSQL driver (`psycopg`, `[binary,pool]` extras)
# used directly throughout adapters/audit/, adapters/lifecycle/,
# adapters/feedback/, and adapters/review/ (ADR-0011). Same reasoning
# already accepted above for chardet: this project uses psycopg as an
# unmodified, unredistributed dependency -- LGPL's linking exception
# applies to exactly this use (importing/calling the library), and only
# imposes its copyleft terms on modifications to psycopg's own source,
# which this project never makes. Explicitly reviewed and accepted by
# Herbert Gourout, 2026-09-03, in response to the supply-chain CI gate's
# first real trigger on this dependency family.
psycopg=LGPL-3.0-only; direct PostgreSQL driver dependency, unmodified/unredistributed, standard dynamic-dependency use permitted under LGPL terms (accepted 2026-09-03)
psycopg-binary=LGPL-3.0-only; same acceptance as psycopg -- binary distribution of the same driver
psycopg-pool=LGPL-3.0-only; same acceptance as psycopg -- connection-pooling extra of the same driver
